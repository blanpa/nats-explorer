# Review notes, September 2026

The decisions behind the current shape of NATS Explorer, with the numbers
that drove them. The changelog has the feature view; this is the "why".

## Decisions

| Decision | Why | Where |
|---|---|---|
| **Pull model for the live feed.** A tab receives only the subject(s) it watches; everything else is recorded server-side and fetched on selection. | The push model sent every tab every subject: browser heap and socket traffic grew with the namespace, not with the screen. | `internal/history`, `lib/feed.ts`, `focus` command |
| **Bounded in-memory history** with a byte budget (`HISTORY_MB`) and a per-subject cap, O(1) eviction via one arrival-ordered FIFO. | Predictable memory, no allocation per eviction. `history.Store` is an interface so a persistent backend (SQLite, DuckDB, JetStream) can replace it. | `internal/history` |
| **Server-side subject tree with per-tab views.** The server keeps the hierarchy and aggregates; a tab sends its expanded paths or a filter and receives only the visible nodes, as exact deltas including removals. | Collapsed branches must cost nothing and the filter must work over namespaces the browser never holds. The reset flag is per tab: a manager-wide flag was consumed by the first tab and left the others stale. | `internal/subscription/tree.go`, `view` command |
| **Feed worker.** The websocket, decoding, tree model, layout and feed coalescing run in a web worker; the main thread renders. | Under load the main thread was spending its time parsing frames and laying out the tree. | `client/src/worker` |
| **MessagePack frames** on request (`?enc=msgpack`), same field names as JSON. | About a fifth less on the wire for the tree feed; JSON stays available for tools and debugging. | `internal/ws/hub.go` |
| **Live subscriptions.** Patterns and system subjects are changed in the Subjects pane while connected, with per-pattern counters; the fields left the connection dialog. | Subscribing is a working decision, not a connection property. Users could not tell what was subscribed. | `PUT /api/connections/{id}/subscriptions`, `SubscriptionsPanel` |
| **Several subjects at once** via Ctrl-click, one live view per subject, merged list. | Watching a machine means watching a handful of subjects together. | `MultiSubjectView`, `focus` takes a list |
| **Series endpoints** downsample a numeric field to min/max buckets, over the history of a subject or the last N sequences of a stream. Subject filtering for streams happens in Go: a filtered ordered consumer resets on every gap and loops. | Charts over thousands of points must not send thousands of points. | `GET /api/history/series`, `GET /api/streams/{name}/series` |
| **One entry point for connections**: the switcher top right with "Manage connections" in its menu. | Three buttons for the same dialog. | `Header`, `ConnectionSwitcher` |
| **Bun, Biome, Vite 8, Vitest 5, TypeScript 7, React 19, Tailwind 4.** | Typecheck 2.6 s → 0.3 s, build 5.0 s → 0.3 s, one tool for lint and format; no visual change after Tailwind 4 (every module compared in both themes). | `package.json`, `biome.json`, `index.css` |
| **Less copy, shorter identifiers.** Empty states and hints carry one sentence at most; server IDs are abbreviated; the number format is locale-independent. | Explanatory text on every surface and 56-character IDs in every row read as generated, not designed. | `ServerName`, `formatCount` |
| **The detail pane shows, it does not hide.** History open by default, sparklines for numeric fields, table columns that fit; the subscriptions panel collapses when it has nothing to say; `/`, Escape, `j`/`k`. | The pane people look at most was mostly empty space with the data behind buttons. | `TrendStrip`, `HistoryRail`, `SubjectText`, `lib/shortcuts.ts` |
| **Charts for streams** use the same chart as subjects, fed by the stream series endpoint. | Same mental model in both modules. | `StreamMessages` |
| **Hot path without a central lock.** Records keep nats.go's bytes and classify lazily; shards by subject hash own the counters, history and rate buckets, fed in batches by a worker each; the tree syncs from the shards per tick. | Profiled at 400 000 msg/s: a third nats.go's parser, the rest spread over JSON validation and copies per message, channel wake-ups, ring compaction and two hashes. Removing those took the backend from 125 % to 83 % of one core. | `internal/subscription/manager.go`, `internal/history`, `message.Record` |
| **Persistent history in SQLite** (`HISTORY_DB`) behind the same `history.Store`: memory stays the hot path, a writer goroutine batches inserts, retention runs once a minute, the UI adds a range picker. | Time ranges and search over days need a disk; SQLite (pure Go driver) needs no service and one file is easy to mount. DuckDB was considered and dropped: CGO build, and the queries here are point lookups and small ranges, not analytics. | `internal/history/sqlite.go`, `RangePicker` |
| **Accounts and roles with a session cookie.** `AUTH_USERS` (bcrypt), `admin` writes and `viewer` reads; the cookie is HttpOnly and carries the websocket too, so no token sits in a URL. Every non-GET under `/api` needs admin. | Sharing an explorer with a team needs read-only access; a token in the websocket URL ends up in logs. Method-based gating cannot miss a route. | `internal/auth`, `lib/auth.ts`, `useCanWrite` |
| **Payload decoders in the browser.** Rules per subject pattern (MessagePack, protobuf from pasted `.proto`, Avro from the schema), libraries loaded on first use. | Binary payloads were a hex dump. Decoding client-side keeps schemas out of the backend and needs no restart. | `lib/decoders.ts`, `DecoderDialog` |
| **Auto-connect and `/metrics`.** With file storage the backend opens flagged connections at start; Prometheus text without a client library. | A headless server that records history must not wait for a browser; ops wants to graph the explorer's own counters. | `autoconnect.go`, `metrics.go` |
| **Component tests with jsdom** next to the pure unit tests; the worker's tree and feed logic is a class with injected scheduling. | The UI logic that decides what a viewer sees or what a subscription change sends was only covered end to end. | `src/test/setup.ts`, `worker/feedCore.ts` |
| **Left out on purpose**: Wails 3 (alpha), swapping the websocket library (no measurable gain), server-side downsampling beyond one field per request, translations. | | |

## Measurements

Load: 5 000 subjects, 6 levels deep, 200-byte JSON payloads at 20 000 msg/s; one headless Chrome tab at 1440×900, 30 s window; backend subscribed with `>`.

| Metric | Push model (v0.2.0) | Pull model | Server tree, worker, MessagePack, tree fully expanded | same, default view |
|---|---|---|---|---|
| Websocket traffic (uncompressed) | 1.80 MB/s | 1.16 MB/s | 1.46 MB/s | 0.01 MB/s |
| Browser main thread busy | 17.0 % | 8.7 % | 4.1 % | 1.5 % |
| Long tasks in 30 s | 31, longest 141 ms | 30, longest 66 ms | none | none |
| Filter keystroke to rows updated | 15–26 ms | 19–24 ms | 108–117 ms (server round trip) | 72–78 ms |
| JS heap | 48 MB | 16 MB | 21 MB | 6 MB |
| Backend | 8 % CPU, 36 MB | 7 % CPU, 431 MB (256 MB history) | 9 % CPU, 431 MB | 7 % CPU, 542 MB |

The fully expanded tree carries subtree totals and child counts per entry, hence more bytes than the flat feed before it; the point of the view-driven feed is the last column. The filter is slower in absolute terms because it runs on the server over the whole namespace.

Earlier in the month (2026-09-05), the flat tree feed with previews and budgets had already brought the push model from 62 % main-thread time and 30 MB/s down to the first column above.

### Backend ceiling

Load generator on 5 000 subjects against the dev NATS, backend subscribed with `>`, 18 s windows. The NATS server spends about as much CPU delivering the copy as the backend spends on it.

| Target | Received | Backend before | Backend after | NATS server |
|---|---|---|---|---|
| 100 000 msg/s | 100 000 | 29 % of one core | 25 % | 28 % |
| 200 000 msg/s | 200 000 | 60 % | (not re-measured) | 53 % |
| 400 000 msg/s | 400 000 | 125 % | 83 % | 102 % |

No throttling, the history stays at its budget. Of the remaining time at 400 000 msg/s roughly a third is nats.go's parser and a fifth the garbage collector; the rest is map lookups and memory traffic across five thousand subject rings.

## Verified against real setups

Mutual TLS server, a three-node cluster with a leaf node and JetStream domains, the stress load above, and the release pipeline on all three desktop platforms (see the 0.2.0 changelog).
